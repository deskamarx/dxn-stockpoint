# Deployment

The recommended production path is **Oracle Cloud Always Free + Docker + Caddy**.
The full walkthrough lives in [../deploy/README.md](../deploy/README.md); this
page covers the options and the details that apply to every path.

Total recurring cost: **$0**.

| Piece | Service | Free-tier limit that matters |
|---|---|---|
| API + database | Oracle Cloud Always Free VM + Docker | 1–4 ARM OCPUs / 6–24 GB RAM, 200 GB block storage |
| HTTPS | Caddy + Let's Encrypt | automatic, unlimited renewals |
| Web app | served by the same VM | same origin, no separate hosting |
| Backups | VM disk + optional Cloudflare R2 | R2 includes 10 GB free |
| Android build + download | GitHub Actions + Releases | 2 000 CI minutes/month |
| Play Store (optional) | Google Play Console | one-off registration fee |

## Option A — Oracle Cloud Always Free (recommended)

1. Create an Ubuntu VM (`VM.Standard.A1.Flex` preferred, `E2.1.Micro` works).
2. Open TCP 80/443 in the Oracle security list.
3. Point a domain's A record at the VM.
4. On the VM: `sudo bash deploy/oracle-bootstrap.sh`.
5. On your computer: fill `deploy/.env`, then
   `DXN_HOST=ubuntu@<ip> DXN_DOMAIN=<domain> ./deploy/deploy.sh`.

Caddy terminates TLS, the Node API runs as an unprivileged container with a
read-only root filesystem, and the JSON database lives on a Docker volume.
Backups, restore, updates and troubleshooting are documented in
[../deploy/README.md](../deploy/README.md).

## Option B — shop PC / LAN

```bash
npm start           # http://127.0.0.1:4173
start-lan.cmd       # same, bound to the LAN with a firewall hint
```

Every phone on the same Wi-Fi can use `http://<shop-pc-ip>:4173`. The Android
apps accept that URL in Settings. No internet required.

## Option C — any Docker host

```bash
docker build -t dxn-stockpoint .
docker run -d --restart unless-stopped -p 4173:4173 \
  --env-file .env -v dxn-data:/app/server/data dxn-stockpoint
```

Put a TLS reverse proxy in front of it. Set `DXN_TRUST_PROXY=1` so rate limits
and logs see real client IPs. Production mode refuses to start with the default
PIN or admin key.

## Option D — PHP 8 shared hosting (legacy)

`api/` still contains the PHP + MySQL implementation for hosts that cannot run
Node. It is not the recommended source of truth any more:

1. Upload `api/` so that `api/public` is the web root.
2. Fill `api/config/config.php`.
3. Open `…/api/public/install.php?key=<admin_key>` once.
4. Point the apps at that origin.

The Node API is where new work happens; the PHP API is kept for compatibility.

## GitHub Pages (web only)

`docs/` can be published as a static site, but GitHub Pages cannot run the API.
Set `<meta name="dxn-api-base" content="https://shop.example.com">` in
`docs/index.html`, or configure the API URL in Settings. The PWA still works
offline from its cache.

## CI secrets

Add these in **Settings → Secrets and variables → Actions**:

| Secret | Purpose |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | owner keystore, `base64 -w0 release.keystore` |
| `ANDROID_KEYSTORE_PASSWORD` | owner keystore password |
| `ANDROID_KEY_ALIAS` | owner key alias (`dxn`) |
| `ANDROID_KEY_PASSWORD` | owner key password |
| `ANDROID_CLIENT_KEYSTORE_BASE64` | customer keystore, generated by `new-client-keystore.sh` |
| `ANDROID_CLIENT_KEYSTORE_PASSWORD` | customer keystore password |
| `ANDROID_CLIENT_KEY_ALIAS` | customer key alias (`dxn-client`) |
| `ANDROID_CLIENT_KEY_PASSWORD` | customer key password |

Without these secrets CI still builds and tests debug APKs and the server; it
does not publish a release.

## Security checklist

- [ ] `DXN_PIN` changed from `2468`; `DXN_ADMIN_KEY` is 32+ random bytes.
- [ ] `deploy/.env` exists only on the server (mode `600`) and in CI secrets.
- [ ] Ports 80/443 open; SSH limited to your IP where possible.
- [ ] DNS proxying/CDN configured without breaking ACME (DNS-only for issuance).
- [ ] Daily backups enabled and a restore has been tested once.
- [ ] Android release APKs signed with the expected certificates
      (`apksigner verify --print-certs`).
- [ ] The API answers `https://<domain>/api/v1/health` with `"status":"ok"`.
